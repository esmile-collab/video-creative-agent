# Video Creative Agent（视频创意智能体）公开版 PRD（产品需求文档）

> 版本：v1.0  
> 日期：2026-08-23  
> 状态：公开工程基线  
> 目标读者：产品、设计、前端、后端、算法与测试

## 1. 最高优先级问题

首发要解决的问题只有一个：

> 用户给出一份有事实边界的 Brief（任务简报）后，能否稳定得到一版可确认的口播脚本和一份不改写原文、可校验、可交付的分镜？

完成条件：一名新用户无需理解内部实现，在一个项目内走完“Brief（任务简报）→ 策略 → 脚本 → 确认 → 分镜 → 校验 → 导出”，任何失败都能定位到具体阶段。

自动理解参考视频、批量生产策略知识、素材召回、TTS（语音合成）和成片渲染不阻塞首发。

## 2. 当前可执行基线

本仓库 v0.1 已具备：

- 已发布策略卡的硬过滤、文本排序、Top-1（第一名）选择、人工覆盖和回退。
- Brief（任务简报）、基础 Skill（生成规则）和策略卡的脚本请求编译。
- Mock Provider（模拟模型供应方）与 OpenAI-compatible Provider（兼容模型供应方）。
- 确认脚本的确定性切分、连续时间、原文冻结和画面说明生成。
- 结构门禁、切点 F1（调和平均指标）、JSON（结构化数据）和 Markdown（可读文档）导出。
- 三条公开视频的外部来源引用，以及无密钥离线 Demo（演示）。
- 本机路径、凭证、私有指标、媒体、大文件与内部域名的公开安全扫描。

当前尚未具备：

- Web UI（网页界面）、账户、数据库、对象存储和异步任务队列。
- 自动 Brief（任务简报）解析、自动视频理解和策略卡自动生产。
- 真实素材召回、音频生成、渲染、合成与成片质检。
- 大样本人工盲评结论。

自动门禁通过只代表结构完整，不能等同于内容和画面质量通过。

## 3. 产品定义

### 3.1 一句话说明

把有事实边界的 Brief（任务简报）转换成可审阅口播脚本与可生产分镜，并保留策略、版本、来源和校验记录。

### 3.2 目标用户

- 独立内容创作者。
- 小型内容和品牌团队中的策划、脚本与剪辑人员。
- 需要把脚本交给设计、数字人或 AI（人工智能）生成工具的制作团队。

### 3.3 首发内容范围

- 中文口播内容。
- 30 秒至 5 分钟。
- 知识讲解、问题解释、产品教育与商业内容。
- 画面由数字人、AI（人工智能）画面、说明性图文和用户素材组合。

### 3.4 暂缓范围

- 剧情短片、纯实拍导演、游戏混剪、音乐视频和长纪录片。
- 一键生成完整成片。
- 从任意网络页面无授权采集媒体。
- 对外宣称策略一定提高流量、转化或商业结果。

## 4. 产品原则

1. 事实与策略分层：当前事实只来自本次 Brief（任务简报）和用户确认资料，策略卡只提供结构与表达方法。
2. 确认后冻结：脚本确认后，分镜阶段不得静默改写口播。
3. 每步有产物：输入、输出、版本、错误和放行条件都可见。
4. 自动检查有边界：结构检查和质量判断分别展示。
5. 来源最小化：公开视频只保存外部引用，媒体缓存需要额外授权。
6. 默认可回退：策略召回失败时允许回到基础生成规则。

## 5. 角色与权限

| 角色 | 主要权限 |
| --- | --- |
| Creator（创作者） | 创建项目、填写 Brief（任务简报）、生成和编辑脚本、生成分镜、导出 |
| Reviewer（审核者） | 评论、确认脚本、确认分镜、驳回并填写原因 |
| Admin（管理员） | 管理 Provider（模型供应方）、策略卡版本、工作区成员与安全设置 |

首发单人版可以合并三个角色，数据结构仍保留角色字段，方便后续团队协作。

## 6. 主流程

```text
创建项目
→ 填写 Brief（任务简报）与事实边界
→ 选择或自动匹配策略
→ 生成脚本草稿
→ 用户编辑并确认脚本版本
→ 生成分镜
→ 修订画面说明
→ 自动结构校验
→ 人工确认
→ 导出 JSON / Markdown（结构化数据 / 可读文档）
```

### 6.1 正常路径

1. 用户新建项目，选择内容类型、时长和目标受众。
2. 用户填写确认事实、创作许可、禁止项与交付要求。
3. 系统对策略卡执行状态、类型、必需输入和排除条件过滤。
4. 系统展示 Top-1（第一名）策略及命中原因，用户可以改选或关闭策略。
5. 系统编译脚本请求并调用模型，保存输入哈希、策略版本和模型信息。
6. 用户编辑脚本并点击“确认脚本”。系统创建不可变确认版本。
7. 系统切分确认脚本、分配时间、生成画面类型和 Caption（画面描述）。
8. 用户逐段编辑画面说明，口播原文保持只读。
9. 系统运行结构校验，展示阻断问题和质量提醒。
10. 人工确认后导出。

### 6.2 失败与回退

| 场景 | 产品行为 |
| --- | --- |
| 没有合格策略卡 | 明示回退到基础 Skill（生成规则），允许继续 |
| Brief（任务简报）缺字段 | 标出缺项，不发起模型调用 |
| 模型调用失败 | 保留本次输入，允许重试或切换 Provider（模型供应方） |
| 脚本未确认 | 禁止生成正式分镜 |
| 分镜破坏确认脚本 | 阻断导出，定位具体段落 |
| Caption（画面描述）为空或模糊 | 阻断或警告，并支持逐段修订 |
| 人工驳回 | 保存原因，回到对应版本继续修改 |

## 7. 功能需求

### F1. 项目与 Brief（任务简报）

必填项：

- `title（项目标题）`
- `script_type（脚本类型）`
- `audience（目标受众）`
- `content_goal（内容目标）`
- `confirmed_facts（确认事实）`
- `creative_permissions（创作许可）`
- `forbidden_claims（禁止项）`
- `duration_range（时长范围）`
- `delivery_requirements（交付要求）`

要求：

- 保存草稿与最近编辑时间。
- 提交前检查必填项。
- 确认事实和禁止项在后续页面持续可见。
- 支持粘贴文本，首发不解析私有文件。

### F2. 策略匹配

要求：

- 只召回 `published（已发布）` 状态策略卡。
- 先执行硬过滤，再做文本排序。
- 默认选择一张卡，展示总分、命中字段和过滤原因。
- 支持用户手动改选、关闭策略或使用回退。
- 记录卡片 ID、版本、分数、查询哈希和选择方式。
- 卡片详情分开呈现 retrieval_view（召回视图）和 generation_view（生成视图）。

验收：相同输入、相同卡库和相同配置得到相同选择结果。

### F3. 脚本生成与版本

要求：

- 系统提示中明确当前事实只来自 Brief（任务简报）。
- 模型只返回最终脚本，不要求展示隐藏推理。
- 保存脚本草稿、模型、策略版本、提示哈希和时间。
- 支持重新生成、手动编辑、版本对比和恢复历史版本。
- “确认脚本”创建不可变版本，后续修改产生新草稿。

阻断项：缺失确认事实、禁止项或输出要求时不得调用模型。

### F4. 分镜生成

每个 Segment（分镜段落）至少包含：

- `segment_id（段落编号）`
- `start_sec（开始秒）`
- `end_sec（结束秒）`
- `asr_text（冻结口播）`
- `visual_type（画面类型）`
- `caption（画面描述）`

画面类型：

- `digital_human（数字人）`
- `ai_visual（AI 画面）`
- `explanatory_graphic（说明性图文）`
- `user_asset（用户素材）`

要求：

- 首发使用确定性切分，结果可重复。
- 时间连续且总时长一致。
- 分镜编辑只开放画面类型和 Caption（画面描述）。
- 修改口播需要回到脚本页，产生新的确认版本后重建分镜。
- 重建前提示旧分镜会成为历史版本。

### F5. 校验与人工确认

阻断检查：

- 段落编号连续。
- 时间连续且结束时间大于开始时间。
- 冻结口播完整保留确认脚本。
- 画面类型合法。
- Caption（画面描述）非空。
- 总时长一致。

质量提醒：

- Caption（画面描述）过长。
- 使用“相关画面”“配合字幕”等模糊描述。
- 连续大量段落使用同一画面类型。
- 用户素材段落没有绑定素材。

系统输出 `blocked（阻断）` 或 `human_review_required（需要人工评审）`。人工评审完成后才能标记 `approved（已通过）`。

### F6. 导出

首发格式：

- `storyboard.json（分镜结构数据）`
- `storyboard.md（分镜可读文档）`
- `script.txt（确认脚本）`
- `validation_report.json（校验报告）`
- `run_summary.json（运行摘要）`

导出包必须包含版本、哈希、校验结果和生成时间，不包含 API Key（接口密钥）与原始鉴权头。

### F7. 公开来源引用

首发保存字段：

- `source_id（来源编号）`
- `platform（来源平台）`
- `public_video_id（公开视频编号）`
- `title（公开标题）`
- `public_url（公开链接）`
- `media_mode（媒体模式）`
- `rights_note（权利说明）`

默认媒体模式为 `external_reference（外部引用）`，仓库和产品服务端不缓存媒体。用户拥有再分发许可时，可在工作区配置独立对象存储。

### F8. Provider（模型供应方）

- 支持 Mock（模拟）和 OpenAI-compatible（兼容协议）两类 Provider（模型供应方）。
- 密钥只在服务端环境变量或密钥管理系统中保存。
- 前端只显示密钥是否已配置，不回显完整值。
- 请求设定超时，错误信息不包含鉴权头和完整响应体。
- 每次运行记录 `provider_id（供应方编号）` 和 `model_id（模型编号）`。

## 8. 前端信息架构

### 8.1 页面

1. 登录与工作区。
2. 项目列表。
3. 新建项目 / Brief（任务简报）。
4. 策略选择。
5. 脚本编辑与版本。
6. 分镜编辑器。
7. 校验与导出。
8. 策略库管理。
9. Provider（模型供应方）与安全设置。

### 8.2 项目工作台布局

- 左侧：阶段导航和完成状态。
- 中间：当前阶段编辑区。
- 右侧：事实边界、来源、策略解释与校验问题。
- 顶部：项目状态、当前版本、保存状态和主操作。

### 8.3 分镜编辑器

桌面端采用表格或卡片列表，每段固定显示：

- 时间轴与段落编号。
- 只读口播原文。
- 画面类型选择。
- Caption（画面描述）编辑框。
- 校验状态与评论。

首发无需复杂轨道式剪辑器。分镜结构稳定后再评估时间轴交互。

## 9. 状态模型

### 9.1 项目状态

```text
draft（草稿）
→ brief_ready（任务简报就绪）
→ script_drafting（脚本编辑中）
→ script_approved（脚本已确认）
→ storyboard_drafting（分镜编辑中）
→ review_required（等待评审）
→ approved（已通过）
→ exported（已导出）
```

`blocked（阻断）` 作为阶段校验状态，不覆盖项目主状态。

### 9.2 版本关系

- Brief（任务简报）、脚本、确认脚本和分镜分别版本化。
- 分镜必须指向唯一确认脚本版本。
- 新确认脚本不会覆盖旧分镜，旧分镜进入历史记录。
- 导出包指向唯一分镜版本和校验报告。

## 10. 核心数据对象

| 对象 | 关键字段 |
| --- | --- |
| Project（项目） | ID、标题、类型、状态、创建者、时间 |
| BriefVersion（任务简报版本） | 项目 ID、版本、字段内容、内容哈希 |
| StrategyCard（策略卡） | ID、版本、状态、召回视图、生成视图、迁移边界 |
| RetrievalRun（召回运行） | 查询哈希、候选、分数、过滤原因、选择方式 |
| ScriptVersion（脚本版本） | 文本、状态、来源运行、内容哈希 |
| StoryboardVersion（分镜版本） | 确认脚本 ID、段落、总时长、内容哈希 |
| ValidationReport（校验报告） | 阻断项、提醒项、放行决定、版本 |
| PublicSource（公开来源） | 平台、公开 ID、标题、链接、媒体模式、权利说明 |
| ExportJob（导出任务） | 分镜版本、格式、状态、文件地址、时间 |

## 11. API（接口）建议

| Method（方法） | Path（路径） | 用途 |
| --- | --- | --- |
| POST（创建） | `/api/projects` | 创建项目 |
| PUT（更新） | `/api/projects/:id/brief` | 保存 Brief（任务简报）草稿 |
| POST（创建） | `/api/projects/:id/retrieval-runs` | 运行策略匹配 |
| POST（创建） | `/api/projects/:id/script-runs` | 生成脚本草稿 |
| POST（创建） | `/api/scripts/:id/approve` | 确认脚本版本 |
| POST（创建） | `/api/scripts/:id/storyboards` | 生成分镜 |
| PUT（更新） | `/api/storyboards/:id/segments/:segmentId` | 更新画面说明 |
| POST（创建） | `/api/storyboards/:id/validate` | 运行校验 |
| POST（创建） | `/api/storyboards/:id/approve` | 人工确认分镜 |
| POST（创建） | `/api/storyboards/:id/exports` | 创建导出任务 |

所有写接口需要工作区鉴权和幂等键。模型生成、分镜生成与导出使用异步任务，前端通过轮询或 SSE（服务端事件）读取进度。

## 12. 技术架构建议

```text
Web UI（网页界面）
→ API（业务接口）
→ Workflow Service（工作流服务）
   ├─ Strategy Core（策略核心）
   ├─ Script Compiler（脚本编译器）
   ├─ Storyboard Core（分镜核心）
   └─ Evaluation Core（评测核心）
→ Job Queue（任务队列）
→ Provider Adapter（模型适配器）
→ PostgreSQL（关系数据库） + Object Storage（对象存储）
```

当前仓库的 `core/` 和 `contracts/` 可直接成为服务端领域层。前端接入前，应先补项目、版本、任务和权限四组持久化对象。

## 13. 安全与公开数据边界

公开仓库允许：

- 通用代码、结构契约、测试和原创 Demo（演示）。
- 公共页面 URL（链接）、公开视频 ID、标题和最小来源说明。
- 不包含业务效果的通用结构分析。

公开仓库禁止：

- 私有业务效果、客户、账户、人员和内部协作信息。
- Cookie（浏览器凭证）、Token（令牌）、API Key（接口密钥）和鉴权记录。
- 内部域名、本机绝对路径、运行会话和原始模型快照。
- 未授权再分发的视频、音频、完整字幕与抽帧。

部署环境还需补充：登录、工作区隔离、速率限制、审计日志、密钥托管、备份与删除机制。

## 14. 非功能要求

- 可重复性：确定性步骤在相同输入下产出一致结果。
- 可追溯性：每次运行保存输入哈希、版本、模型与校验报告。
- 可恢复性：模型失败后可重试，不丢失用户编辑内容。
- 性能：非模型接口 P95（95 分位响应时间）低于 500 毫秒；长任务异步执行。
- 可访问性：核心流程支持键盘操作，状态不只依赖颜色传达。
- 浏览器：支持最近两个稳定版本的 Chrome（浏览器）、Safari（浏览器）与 Edge（浏览器）。
- 隐私：日志不记录完整密钥、鉴权头和用户私有素材正文。

## 15. 产品质量与观测

首发关注四类指标，公开文档不预设目标值：

- Activation（激活）：创建项目后成功导出首份分镜的用户比例。
- Completion（完成）：各阶段进入下一阶段的比例和阻断原因。
- Reliability（可靠性）：模型调用成功率、任务重试率和结构门禁通过率。
- Quality（质量）：人工确认率、分镜逐段修改率和盲评偏好。

这些指标用于产品自身改进，不接入任何来源平台的私有消耗或曝光数据。

## 16. 发布计划

### M0. 公开工程基线（当前）

- 核心代码、契约、原创 Demo（演示）、脱敏扫描和测试。
- 完成条件：`npm run verify` 全部通过。

### M1. 可用 Web（网页）产品

- 账户、工作区、项目、Brief（任务简报）、策略、脚本、分镜、校验和导出。
- 数据库、任务队列、模型配置和基础审计日志。
- 完成条件：新用户可在界面完成首条分镜导出，失败可恢复。

### M2. 授权参考视频

- 用户上传、对象存储、ASR（自动语音识别）、OCR（光学文字识别）、抽帧和证据浏览。
- 策略卡生产、人工复核和发布流程。
- 完成条件：来源可追溯，媒体权利状态明确，策略发布需要人工确认。

### M3. 生产增强

- 素材召回、TTS（语音合成）、多渲染器、时间轴和成片导出。
- 受控盲评、质量回归和费用保护。
- 完成条件：至少一个内容类型形成稳定生产闭环。

## 17. 首发验收清单

- [ ] 用户能创建、保存和恢复项目。
- [ ] Brief（任务简报）缺项时不会调用模型。
- [ ] 策略选择原因、版本和回退状态可见。
- [ ] 脚本有草稿、确认和历史版本。
- [ ] 分镜不能改写确认脚本。
- [ ] 校验能定位段落级阻断问题。
- [ ] 人工确认前不能标记最终通过。
- [ ] 导出包包含脚本、分镜、校验报告和版本信息。
- [ ] Provider（模型供应方）密钥不进入前端和日志。
- [ ] 公开视频仅以外部引用展示。
- [ ] 脱敏扫描、单元测试和离线 Demo（演示）在持续集成中通过。
- [ ] 版权、隐私、删除和许可证说明发布前完成人工复核。

## 18. 上线前待决策

1. 开源代码许可证。
2. 单人优先或团队协作优先。
3. 首个真实模型 Provider（模型供应方）与费用上限。
4. 登录、数据库、对象存储和部署平台。
5. 首发是否开放策略库管理端。
6. 用户上传媒体的权利声明、保存周期和删除策略。

这六项会影响前端信息架构和部署成本，应在 M1（可用网页产品）开发前确认。
